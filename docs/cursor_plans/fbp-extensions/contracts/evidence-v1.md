## Identity before artifacts

Host BuildManifest `{version:1,files:[{path,sha256}],lockDigest,toolchain:{node,compiler},dependencyRoles:[{role,implementationDigest,fixtureProfileDigest}]}`. UTF-8 POSIX relative paths, no traversal/absolute paths, unique and sorted lexicographically; digest lowercase64 hex; unknown fields refuse. Host tooling enumerates declared packaged/application handler dependency closure as build inputs, hashes exact emitted runtime bytes plus manifest/lock/policy versions. No function.toString(), timestamps, captured service objects or credentials.

`implementationDigest = SHA256(canonical({format:'nodeflow.implementation',version:1,manifest:BuildManifest}))`. Canonical sorts keys, preserves arrays, rejects non-JSON/nonfinite and normalizes negative0 to0 with ordinary JSON number serialization. Object names/paths preserve Unicode, no normalization. Build manifest is trusted host provenance, not cryptographic proof against a lying host or of unlisted dynamic dependencies. Missing declaration/digest marks identity unverified and blocks “reproducible” claims, not ordinary execution.

Execution identity preimage `{format:'nodeflow.execution',version:1,graph,bindings:[{component,implementationDigest,contractsDigest}],runtimeVersion,policyVersion,serviceProfileDigest}` sorted bindings by component. Contract digest includes canonical port/config schema/representation identity. Graph arrays preserve authored order. RunId/jobId/packetId/time are excluded. S24B owns identity builder/validation in existing core observation/testing boundary, not future artifact package. S32 reuses canonical primitive and maps execution identity to semantic artifact revision; it must not introduce a competing implementation hash algorithm.

Code digest changes on a local workspace rebuild and invalidates comparisons/locked receipts; never mutate already-started run bindings. Exact trusted build input manifest is supplied by application/packaging tool, not inferred from arbitrary application code. S24B.A requires a fixture with a changed transitive helper and rejects an incomplete manifest marked unverified. Dynamic dependency discovery remains F03.

## Decision declaration

Component/FunctionSpec optional `decisions: readonly {code,ruleVersion,outcomes,facts:readonly string[]}[]`; metadata is browser-safe, declarations unique by `(code,ruleVersion)`, no handler functions. Catalog extension uses an explicitly versioned diagnostic descriptor alongside existing catalog1 until configured catalog2 owns integration; do not add unknown fields to current strict catalog1 silently.

TaskContext adds nonthrowing `recordDecision({code,ruleVersion,outcome,facts})` only in S24A. Facts are `{name,sourcePacketId?,fieldPath?}` references, max16, fieldPath a JSON Pointer string≤256characters. Accept only declared names/codes/outcomes, only packet IDs from task's actual bound inputs, and current active attempt context. Node-scope decision may omit packet references; no fake packet parent. Rejected records increment safe rejection counters and do not alter task result. Business rule values remain subject to capture policy.

Observation uses a separately versioned DecisionRecord `{format:'nodeflow.decision',version:1,runId,sequence,timeMs,nodeId,operationId,attemptId,attempt,inputs,code,ruleVersion,outcome,facts}` correlated to DG1 operation/attempt and authoritative bound input metadata. Decision sequence is scoped to its decision stream; evidence references use (stream,sequence), never a shared assumed counter. This does not add unknown variants to strict DG1-v1 or EX1. S24A records decisions through the same bounded observer owner with a combined retention ceiling; S24B joins the two record types in an evidence-v1 envelope. Runtime reports actual filter keep/drop separately from the node’s declared reason; mismatch is visible. Labels distinguish “observed predicate=false” from “node reports BELOW_THRESHOLD/rule-v1.” No automatic access to private algorithm reasoning. Late task context cannot emit as a new active attempt.

## Explanation output and completeness

`{version:1,runId,subject,coverage,nodes,links,gaps}` is passive browser-safe JSON. Subject `{kind:'input'|'output',packetId,jobId}` must belong to authorized selected run. Each explanation node references exact retained record sequence; each link is packet-parent or explicit operation binding. Gap `{kind,reference?}` uses enum `evicted|capture-off|oversize|disconnect|missing-parent|reason-undeclared|identity-unverified`. Code/operation duration require their actual observed records, not chronological proximity.

coverage enum `complete-for-recorded-scope|partial|unavailable`: completeness requires known ingress/all referenced links and no retained-interval gaps. Uncaptured payload independently marked. Query max1024 records and cycle/duplicate traversal protection; malformed/cross-run input refuses INVALID_EXPLANATION, unknown retained subject yields unavailable rather than arbitrary global lookup. No claim complete-for-recorded-scope explains all internal business reasoning.

## Fixtures and comparison

Fixture-v1 `{format:'nodeflow.fixture',version:1,caseId,executionIdentity,input,dependencyScripts,expected,redactionReview,provenance}`. input is named port→ordered reviewed JSON packet values with stable case/job mapping; generated runtime IDs fresh. dependencyScripts is named trusted role→ordered result/error data; no URL/module/function/source. expected contains explicit output-value/multiplicity/order and declared decision assertions. provenance labels recorded versus synthetic fields/known evidence gaps; redactionReview includes reviewed paths/synthetic substitutions and host-issued review ID.

Host issues review ID only after configured field allowlist and explicit authorized human review of exported data; it is not proof an arbitrary free-text secret detector is infallible. Redacted values/expectations must still satisfy registered contracts; missing essential payload or unverified dependency facts refuses FIXTURE_INCOMPLETE. Import/export unknown fields/version→INVALID_FIXTURE; untrusted binding→BINDING_MISMATCH. Default generated test runs offline against caller-owned injected fixture role implementations through public /testing. No automatic invocation/import of captured services/source and no overwrite of edited handwritten files.

Comparison pair must share fixture and dependency-script digests with explicit baseline/candidate graph/code identities. Bindings unavailable or mismatched facts→not-comparable, no external fallback. Use case/logical node/origin/port/occurrence identities; ignore random runtime IDs and wall-time noise for semantic equality. Compare values/multiplicity/order/decisions/errors/path; declare equal-on-fixtures or changed-on-fixtures only for covered facts. Performance observations separate. Bad assertions exported from an observed bad run require human correction; recording is not an oracle.
